What is Dataporter?

Built for the way real file migrations actually go wrong

Large migrations rarely fail all at once — a handful of files error out, a job gets interrupted, someone re-runs it next week against a half-populated destination. Dataporter is designed around that reality, not a single clean pass.

Features

Everything a migration needs

Discover, transfer, verify, and cut over — with a record of every step.

Discovery & inventory

Walk a source file server first and get a complete, queryable inventory — file counts, sizes, and paths — before anything is copied.

Streaming transfer

Files stream through a bounded pipe instead of being buffered whole — a 200 GB file costs the same RAM as a 2 MB one.

Incremental re-sync

Unchanged files are skipped, metadata-only changes are stamped without moving data, and only real changes are copied.

Per-file fault tolerance

One bad file doesn't stop the job. Dataporter logs it, keeps going, and reports exactly what failed and why.

Kubernetes-native worker

Runs as an ordinary pod — no privileged mode, no kernel mounts — even against NFS exports that require a reserved source port.

Full audit trail

Every job run, every file, every retry is recorded — so a cutover decision is backed by a report, not a guess.

How it works

Four steps, start to cutover

  1. 01

    Register

    Point Dataporter at the source and destination — NFS or SMB shares, on-prem or cloud-hosted.

  2. 02

    Discover

    Inventory the source first, so you know exactly how much is about to move.

  3. 03

    Migrate

    Watch files, throughput, and errors live — concurrent transfers, one job record per run.

  4. 04

    Verify & cut over

    Re-run near cutover — migrated files are skipped, not re-copied — then switch users over.

Security & deployment

Runs inside your infrastructure, not ours

Dataporter deploys into your own Kubernetes cluster or container environment. File data moves directly between your source and destination — never through a third-party service.

  • Self-hosted by default. No external service in the data path.
  • No privileged containers. Speaks NFS from userspace — no kernel mounts.
  • Works with secured exports. Supports reserved source ports without broad host privileges.
  • Every action is logged. Config, run history, and per-file outcomes stay queryable.
